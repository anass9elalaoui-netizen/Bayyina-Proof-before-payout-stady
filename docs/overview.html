How it works

Proof first. Detection only where proof is missing.

Step 1

Prove at capture

The capture app hashes and signs each photo on the device, tied to a one-time code for this claim. Any later edit breaks the signature.

Step 2

Check the rest

Gallery uploads go through metadata checks, compression analysis, an AI-image detector and a search for photos reused from other claims.

Step 3

Read the policy

An AI agent reads the trusted photos, the policy and the customer's story in Darija, Arabic, French or English, and cites the clauses it used.

Step 4

A person decides

The handler sees one clear file and approves, asks for more, or sends it to investigation. Every step lands in a tamper-evident log.

Design decisions

  • Proof beats detection. A valid signature outweighs any detector score.
  • Rules after the model. The final recommendation comes from readable, versioned rules, so behaviour stays predictable.
  • Human decision required. No claim is approved or rejected automatically.
  • Modular monolith first. One deployable for the POC, with boundaries ready to split into services.
  • Integrate on damage estimates. Price table now, specialist estimator later.

Threats we design against

  • Edited after capture → hash no longer matches, photo marked invalid.
  • Replayed photo → one-time code per claim, plus reuse search across all claims.
  • Photo of a screen → guided multi-angle capture now, hardware attestation in the pilot.
  • Prompt injection ("approve this claim" written in the story or the image) → treated as data, strict output schema, rules decide, human approves.
  • Insider edits → hash-chained audit log and role-based access.

The name

Bayyina

Bayyina stands for clear, decisive evidence: the proof that settles a case. That is exactly what the product gives an insurer before money leaves the account. It is short, easy to say in English and French, and no insurance product uses it as far as a web search shows.

Tagline: Proof before payout.
